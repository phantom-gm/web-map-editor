# MSW 웹 맵 에디터 (MVP)

MSW 아이소 RPG용 맵 편집기. 아이소메트릭(2:1 다이아몬드) 그리드에 타일을 칠하고 **blueprint JSON**으로 export → 기존 빌드/런타임 파이프라인에 연결.

> 설계: [`../../docs/map/WEB_MAP_EDITOR_MVP_DESIGN.md`](../../docs/map/WEB_MAP_EDITOR_MVP_DESIGN.md)
> 파이프라인: [`../../docs/map/WEB_MAP_EDITOR_PIPELINE.md`](../../docs/map/WEB_MAP_EDITOR_PIPELINE.md)
> RUID 연동/백엔드: [`../../docs/map/WEB_MAP_EDITOR_RUID_LINKAGE.md`](../../docs/map/WEB_MAP_EDITOR_RUID_LINKAGE.md)
> Vercel 배포: [`../../docs/map/WEB_MAP_EDITOR_DEPLOY.md`](../../docs/map/WEB_MAP_EDITOR_DEPLOY.md)

## 스택 / 실행

**Next.js 14 (App Router) + React 18 + Zustand + Canvas 2D.** Vercel 배포 + RUID 백엔드(`/api`)를 위해
Vite SPA 에서 Next.js 로 마이그레이션(에디터 로직 `src/*` 는 그대로, 셸만 `app/`). 에디터는 `app/page.tsx`
의 `"use client"` 경계에서 `src/App` 트리를 렌더.

```bash
cd tools/web-map-editor
npm install
npm run dev      # http://localhost:3000
```

게임 저장소가 형제 폴더가 아니면 에디터 루트의 `.env.local`에 경로를 지정합니다.
`sync:npc`, `dev`, `build`가 이 경로에서 NPC·몬스터 카탈로그를 갱신합니다.

```dotenv
MSW_GAME_ROOT=C:/Trunk/legend_of_light
```

명시한 경로의 CSV가 누락되면 기존 seed를 보존하고 실패합니다.
경로를 설정하지 않은 배포 환경은 기존처럼 커밋된 seed를 사용합니다.

기타: `npm run build`(`next build`), `npm run start`, `npm run typecheck`, `npm run lint`, `npm run test`.
백엔드 `/api`(resolve/upload)는 RUID 연동 Phase B — 위 RUID_LINKAGE 문서 참조.

## 현재 구현 (M1 ~ M5 + RUID Phase A)

- Next.js (App Router) + React + TypeScript + Zustand + Canvas 2D
- **아이소메트릭(2:1 다이아몬드) 그리드** 렌더 + 호버 셀 + 뷰 맞춤(fit) + **뷰포트 컬링**(큰 맵에서도 부드럽게)
- **팔레트**: **리소스 찾기**에서 MSW 서버 소재를 검색·분류하고, 확인된 이미지를 팔레트에 추가해 선택합니다. 게임 맵에서는 현재 기준에서 지원하는 바닥 소재를 표시하며, 건물·장식은 원본 목록에서 선택합니다.
- **도구**: 브러시 · **사각채우기(rect, 드래그 미리보기)** · 지우개 · **이동불가(block)** · **스포이드(eyedropper)**
- **이동불가 표시**: `이동불가` 도구로 좌드래그 마킹(빨강 다이아몬드 오버레이) · 지우개로 해제.
  게임의 보행불가 셀(`TileAttributeTileMap`)에 매핑 → import/export 왕복 유지
- **undo/redo**: ⌘/Ctrl+Z · ⇧+Z (스트로크 단위, ground+이동불가 함께 스냅샷, 최대 100)
- **입력**: 좌클릭/드래그 = 도구 · 스페이스+드래그 또는 휠클릭 = 팬 · 휠 = 줌
- **경계 클램프**: 페인팅은 size 안으로만, export 시 size 밖 셀은 무시(`buildBlueprint`).
- **검증**: export 전 `validateMap`(빈 맵 · 경계 밖 셀 · 팔레트 범위 초과) → 문제 시 확인 다이얼로그.
- **1×1 오브젝트 정렬 바닥선**(2026-09-26, 게임 MS-26 미러): `offsetY` 가 커서 바닥선이 앞 칸(남쪽 이웃) 중심에 붙거나 넘으면
  캔버스 ▼ 배지(주황 경고 / 빨강 = 게임 빌드 게이트가 막음) + 인스펙터 경고(권장 11px 버튼) + 상태바 건수 + export 검증.
  오브젝트를 선택하면 **정렬 바닥선**과 앞 칸 중심(점선·점)이 그려진다. 같은 RUID 를 새로 놓으면 마지막 저작값이 기본으로 채워진다.
  상세: [`DEPTH_SORT.md`](DEPTH_SORT.md) §"1×1 오브젝트는 바닥선이 곧 순서다".
- **멀티셀 정렬 경계 `sortPadX`**(2026-09-28, 게임 AA-4): 인스펙터 숫자 입력(0 이상 · 0.5 단위) + 선택한 멀티셀 오브젝트의
  정렬 게이트 경계를 분홍 세로선으로(패딩 0 자리는 점선). 산식은 게임 `SortGateSpan` 미러. 상세: [`DEPTH_SORT.md`](DEPTH_SORT.md) §"멀티셀은 정렬 게이트".
- **저장 무손실 · 손수정 확인**(2026-09-28): 무변경 저장은 게임 json 을 한 글자도 바꾸지 않고(파생 필드 재계산·offset 정확 반올림),
  게임 쪽이 json 파생 필드를 직접 고친 값이 저장으로 되돌아가게 되면 저장 전에 확인받는다. 상세: 같은 문서 §"저장이 게임 값을 조용히 바꾸지 않는다".
- **Import/Export**: 기존 `map_blueprint_<Map>.json` 왕복. Ground·이동불가(Attribute) 편집,
  Static 레이어와 origin/palette 는 **verbatim 보존** → round-trip diff 0 (vitest 게이트).
  Attribute 레이어는 이동불가 Set 에서 **재생성**되며 원본과 의미적으로 동일함을 테스트로 검증
- **기존 소재의 RUID 연결**: 일반 프로젝트 팔레트의 **기존 프로젝트 연결 도구**에서 **미연결 소재 서버 조회** 또는 **RUID 연결 파일 읽기**로 기존 소재를 연결합니다. 이전 데이터는 보존하며, 서버와 연결된 소재만 새로 배치합니다.
  **고급 도구 → RUID 매핑 내보내기…**로 `palette_ruids_<Map>.json`을 내보낼 수 있습니다. 게임 맵의 출력은 아래 **게임용 출력 만들기**를 사용합니다.
  레지스트리 생성: `node scripts/build_tile_registry.cjs`(레포 루트, 로컬 `.sprite`→레지스트리, 업로드 0).
  설계: [`../../docs/map/WEB_MAP_EDITOR_RUID_LINKAGE.md`](../../docs/map/WEB_MAP_EDITOR_RUID_LINKAGE.md)

내부 셀 `(gx, gy)`. 편집뷰는 **아이소 다이아몬드**(`src/lib/grid.ts`, TW 64 / TH 32 px), 엔진 규약과 동일(X+1=SE, Y+1=SW, (0,0)=상단). 엔진 world-unit 정합 미러는 `src/lib/iso.ts`(TILE_W 0.56 / TILE_H 0.28 / ORIGIN 15) — round-trip 검증용.

## 게임 맵 작업·실제 배치 미리보기

로컬 `MSW_GAME_ROOT`의 **현재 .map 파일**을 기준으로 편집을 시작합니다.
게임 폴더에는 쓰지 않습니다. 현재 4×4·2×2·1×1 배치, RUID, 위치, 배율, 엔티티를
그대로 보존합니다. 바닥 수정은 겹치는 기존 블록만 재구성하고, 오브젝트 수정은 선택한
원본의 위치·깊이 메타만 갱신합니다. 함께 옮길 이동불가 셀을 직접 선택하면 오브젝트와
한 묶음으로 이동·복제·삭제할 수 있습니다.

1. `npm run dev` 실행 후 `http://127.0.0.1:3000/`에 접속합니다. 실행 스크립트가 로컬 주소로 서버를 시작합니다.
2. 상단 **게임 맵 열기**에서 맵을 고르고 **맵 열기**를 누릅니다. 저장된 작업이 있으면 이어 열고, 처음이면 실제 게임 배치를 가져옵니다.
3. 바닥 소재를 고르거나 **건물·장식·오브젝트 바닥**에서 대상을 선택해 수정합니다. **이동불가 칸 선택**으로 함께 옮길 셀을 추가할 수 있고, **이동불가 도구**로 셀 자체를 만들거나 지웁니다.
4. 1초 뒤 **이 PC에 저장됨**을 확인하거나 **작업 저장 / Ctrl+S**를 누릅니다. 별도 synced 파일 선택은 필요 없습니다.
5. **게임용 출력 만들기**를 누릅니다. 무변경이면 화면에 **원본 맵과 완전 일치**가 표시됩니다.
6. 결과는 `.game-sync/candidates/<map>-<id>/`에 있습니다:
   - `map/<map>.map`: 적용을 검토할 후보 맵 한 개. 이동불가 셀만 바꾸면 원본 맵 바이트를 그대로 복사합니다.
   - `RootDesk/.../DT_Walk.csv`: 이동불가 셀을 바꾼 경우에만 생성하는 적용 검토용 CSV.
   - `RootDesk/.../npc/DT_NpcSpawn.csv`: NPC를 바꾼 경우에만 생성하는 적용 검토용 CSV.
   - `report.json`: 원본/후보 SHA-256, 블록 수, 오브젝트 변경 수, 이동불가 변경 셀, 보존 검증과 `applyFiles` 목록.
   - `editor-project.json`: 다시 편집할 프로젝트.
   - `reference/RootDesk/...`: NPC·몬스터·포털·이동불가·함정 검증에 필요한 CSV 원본 사본. 게임 반영 파일이 아닙니다. 서버 비밀 설정과 무관한 테이블은 복사하지 않습니다.

현재 게임 배치는 `.map`과 런타임 CSV를 기준으로 유지합니다. 이전 `map/<map>.json`은 현재 배치를 모두 담지 않을 수 있으므로 기존 게임 맵에 `nocode_map --build`·`convert_map --apply`·`build_map`을 다시 실행하는 경로는 기본적으로 차단됩니다. 게임 맵을 수정할 때는 위 후보 출력 경로를 사용하세요. 구형 JSON으로 전체 재생성이 의도된 경우에만 게임 도구의 `--allow-legacy-rebuild`를 명시합니다. `--force`는 이 보호를 우회하지 않습니다.

휠 확대 중에도 스트로크는 이어집니다. 창 포커스를 잃으면 마지막 위치에서 작업을 마쳐 실행 취소 기록에 남기며, `Esc`는 진행 중 작업을 취소합니다. 자동저장은 리소스 검색창과 선택을 유지합니다. 정렬 변경 후보는 게임 깊이 검사와 대조해 새 오류가 있으면 출력을 거부하며, 결과는 `report.json`의 `gameDepthValidation`에 기록합니다.

이전 보관 파일의 서버 비밀 CSV 중복 사본을 정리하려면 `node scripts/game-sync/prune-sensitive-references.cjs`로 계획을 확인하고 `--apply`로 실행합니다. 게임 원본과 저장 프로젝트는 보존하고 기준·NPC·런타임·후보의 연결 해시를 함께 갱신합니다. `.game-sync/maintenance/`에 CSV 내용을 포함하지 않는 복구용 메타데이터를 보관합니다.

`.game-sync/baselines/<id>/`는 저장한 프로젝트가 참조하는 기준 스냅샷입니다.
작업은 `.game-sync/workspaces/<map>/project.json`, 이전 저장본은 같은 폴더의 `history/`에 보관합니다.
프로젝트를 계속 편집하려면 `.game-sync/` 전체를 보관하세요. 다른 PC로 옮길 때도 기준 폴더와
게임 checkout이 필요합니다. 기준은 원본 경로/해시를 검사하므로 PC 이동 시 새 동기화가 필요합니다.
`.game-sync/` 전체는 Git에서 제외됩니다.

**바닥·정적 오브젝트·이동불가 셀·NPC·몬스터 출현·포털·시작 위치를 편집할 수 있습니다.** 오브젝트는 원래 그림의
오프셋을 보존하며 셀 단위로 움직입니다. **원본 소재로 추가**에서는 이 맵의 원본 모양을
선택한 뒤 위치를 클릭해 배치합니다. 복제는 회전·배율·반전·색·깊이 메타 등 원본
컴포넌트를 유지합니다. 기존 엔티티의 ID는 유지하고 새 복제에는 새 ID를 부여합니다.

### 여러 오브젝트와 이동불가 셀 함께 편집하기

1. 캔버스나 목록에서 **Ctrl/Shift+클릭**하면 오브젝트를 선택하거나 선택 해제합니다.
   **여러 개 선택**을 켜면 보조 키 없이 클릭으로 선택을 바꿀 수 있습니다.
   **Shift+빈 곳 드래그**는 범위와 그림의 경계 상자가 겹치는 오브젝트를 기존 선택에 추가합니다.
2. **이동불가 칸 선택**으로 전환합니다. 기존 빨간 셀을 클릭하면 선택·해제되고,
   드래그하면 범위 안의 기존 이동불가 셀을 선택에 추가합니다. 새 차단 셀을 만드는 모드는
   아닙니다. 함께 편집할 셀은 하늘색으로 표시되며, 오브젝트 선택은 유지됩니다.
3. **오브젝트 선택**으로 돌아가 선택한 대상을 잡아 드래그하거나 **방향키**로 한 칸씩
   옮깁니다. **X 이동 칸 / Y 이동 칸**에 정수 이동량을 넣고 **지정한 칸만큼 이동**을
   누를 수도 있습니다. 이동불가 셀만 선택한 묶음도 같은 방식으로 편집합니다.
4. **지정한 칸에 복제**는 입력한 X/Y 이동량만큼 떨어진 위치에 묶음을 복제합니다.
   **Ctrl+D**는 X 방향 한 칸 `(+1, 0)`에 복제합니다. **Del**은 선택한 오브젝트와
   선택한 이동불가 셀을 모두 삭제합니다.
5. **Ctrl+Z 한 번**으로 오브젝트와 이동불가 셀을 함께 되돌립니다. **Ctrl+Y** 또는
   **Ctrl+Shift+Z**로 다시 실행할 수 있습니다. **Esc**는 선택을 해제합니다.

오브젝트를 새로 단일 선택하면 이전 이동불가 선택도 비워집니다. 묶음을 구성한 뒤에는
보조 키 없이 **이미 선택한 대상**을 잡아 이동하세요. **이동불가 선택 비우기**는
오브젝트 선택을 유지한 채 셀 선택만 해제합니다.

함께 움직이는 셀은 **직접 선택한 셀뿐**입니다. 건물·나무의 차단 영역은 다른 오브젝트나
수동 차단과 겹칠 수 있으므로 자동으로 연결하지 않습니다. 오브젝트만 선택해 편집하면
이동불가 셀은 그대로입니다. 셀 자체의 추가·제거는 **이동불가 도구**로 수행합니다.

- 이동할 셀이 **선택하지 않은 기존 이동불가 셀**과 겹치거나 맵 밖으로 나가면
  오브젝트를 포함한 전체 작업을 취소합니다. 선택한 셀끼리는 동시에 옮길 수 있습니다.
- 복제할 셀은 **모든 기존 이동불가 셀**과 겹칠 수 없습니다. 복제 위치가 원래 선택 영역에
  걸치면 X/Y 이동량을 늘리거나 바꿔 주세요.
- 지원하지 않는 오브젝트가 섞였거나 미리보기가 현재 편집보다 오래되었으면 부분 적용하지
  않고 작업을 거절합니다. 안내를 확인하고 미리보기 갱신 후 다시 선택하세요.

선택 묶음은 현재 편집 세션에만 존재하며 프로젝트를 열거나 되돌리기·다시 실행을 하면
해제됩니다. 묶음으로 바꾼 **실제 배치와 이동불가 셀은 자동 저장·작업 저장·후보 출력**에
함께 반영됩니다.

원본 DT_Walk와 기준 셀이 일치하는 맵에서만 이동불가 편집을 지원합니다. 후보 CSV는
현재 맵의 명시적 수정만 반영하고 다른 맵의 행·미수정 행은 원문을 보존합니다.
적용 대상은 `report.json`의 `applyFiles`로 확인하세요. `reference/` 파일은 적용 대상이 아닙니다.

### 지원 범위와 원본 보존

맵 크기와 지원하지 않는 스크립트·자식·참조를 가진 오브젝트는
원본을 보호합니다. 표준 바닥을 해석할 수 없는 맵도 검증된 오브젝트 바닥은 별도로
선택·이동·복제할 수 있습니다. 새 일반 바닥 소재는 등록된 페른델 1×1 타일을 사용하며,
길 경계는 1×1 방향 타일을 유지합니다.

**게임 배치 보기**는 후보 출력과 같은 배치 계산을 사용합니다. 실제 .map의 4×4·2×2·1×1
Sprite, 좌표·배율·회전·반전·색·정렬과 원본 이미지 크기·피벗·PPU를 반영합니다.
좌표는 게임의 현재 build_map 상수(TILE_W=2.56, TILE_H=1.28)를 가져오며, 기존 iso.ts의
0.56/0.28 미러는 일반 프로젝트용으로 남깁니다. 이미지 조회는 RUID 직접 조회라
기존 4,000개 목록 한도로 빠지던 오래된 나무·건물도 표시합니다.

4×4 안의 한 칸을 수정하면 해당 블록의 무늬가 작은 타일 조합으로 달라질 수 있습니다.
미리보기에서도 그 재구성 결과를 보여주고, 영향 범위를 출력 결과에 표시합니다.
기본은 편집 장식이 없는 정적 맵 보기입니다. **편집 표시**로 격자·이동불가·스폰 위치
마커를 켤 수 있습니다. NPC·몬스터는 별도 배치표의 대기 외형을, 포털은 실제 표시 리소스를 읽습니다.
움직임·전투·그 밖의 런타임 효과는 재현하지 않습니다. 미해석 이미지·지원 밖 변형은 경고로 표시합니다.

자동 저장은 원본 게임이 변경돼도 작업을 보관합니다. 미리보기·후보 출력은 원본 변경을
계속 검사합니다. **표시·진단 정보 · 원본 관리 → 게임 원본 다시 가져오기…**로 새 기준을
시작하면 이전 저장본은 history에 남습니다. 다른 창과 저장 버전이 충돌하면 덮어쓰지 않고
중단합니다. 파일 사본을 보관한 뒤 **저장본 다시 열기**로 이어갈 수 있습니다.
**파일·백업** 메뉴의 사본 저장/열기는 수동 백업 및 이전 synced 프로젝트를 여는 용도입니다.

게임 맵·원본 프로젝트·리소스 목록·변환 기준이 동기화 이후 변경되면 후보 생성을 거절합니다.
기존 편집을 먼저 다른 이름으로 저장하고 최신 게임 맵을 다시 가져오세요.
오래된 프로젝트를 새 기준으로 자동 덮어맞추지 않습니다.
CSV 변경은 바닥·오브젝트 출력을 막지 않습니다. 출력 시점의 최신 CSV를 참고용으로
복사하고, 기준 이후 추가·수정·삭제 내역을 `report.json`에 기록합니다. 이동불가 셀을
출력할 때는 **현재 맵의 DT_Walk 행이 기준 이후 바뀌면 거절**합니다. 다른 맵의 최신 행은
그대로 보존해 후보 CSV에 합칩니다. 출력 도중 CSV가 바뀌면 다시 굽도록 안내합니다.
무변경이면 원본 맵과 참고 CSV 바이트가 유지되고, 오브젝트만 수정하면 DT_Walk 후보를
생성하지 않습니다. 게임 원본에 자동으로 적용하는 단계는 없습니다.
기존 blueprint Export / 게임 `nocode_map --build`는 이 동기화 계약을 소비하지 않으므로
연결 프로젝트에서는 이 Export 버튼을 숨깁니다. **게임용 출력 만들기**를 사용하세요.

CLI (에디터 폴더에서 실행):

```powershell
npm run game:sync -- create --game-root "C:/Trunk/legend_of_light" --map ferendel --baseline-root ".game-sync/baselines"
npm run game:sync -- export --game-root "C:/Trunk/legend_of_light" --project "<저장한 synced.json>" --baseline-root ".game-sync/baselines" --output-root ".game-sync/candidates"
npm run test:game-sync
$env:MSW_GAME_SYNC_TEST_ROOT = "C:/Trunk/legend_of_light"
npm run test -- src/__tests__/gameSyncIntegration.test.ts
```

검증은 게임 밖 임시 폴더에서 수행합니다. 게임 반영, Maker Refresh/Play는 별도 단계이며
이 기능은 자동으로 실행하지 않습니다. 서버 API는 localhost 요청과 명시적인 게임 경로가
있는 로컬 실행에서만 활성화됩니다.

## 원본과 수정본 비교 (5차)

편집한 게임 맵에서 상단 **원본과 비교**를 누르면 보기 전용 비교 화면으로 전환됩니다.
여기서 **원본**은 이 작업을 처음 가져올 때 `.game-sync/baselines/<id>/`에 보관한
기준 스냅샷입니다. 비교 기준은 해당 작업에 고정되며, 현재 게임 폴더를 다시 가져와
최신 상태로 바꾸지 않습니다.

1. **원본 보기 / 수정본 보기 / 변경 강조**로 화면을 전환합니다. 전환해도 카메라 위치와
   확대 배율이 유지되어 같은 장소의 전후 모습을 볼 수 있습니다.
2. 드래그하면 화면을 이동하고 휠로 확대·축소합니다. 비교 화면에서는 타일 칠하기,
   오브젝트 선택·이동·복제·삭제, 이동불가 편집과 되돌리기·다시 실행을 할 수 없습니다.
3. 왼쪽 **변경 내역**에서 **바닥 / 오브젝트 / NPC / 몬스터 출현 / 포털 / 시작 위치 / 이동불가** 종류를 골라 목록과 강조 표시를
   걸러 봅니다. 직접 수정한 바닥 칸과 주변 재구성 칸, 오브젝트 이동·추가·삭제,
   이동불가 추가·해제 수량을 각각 확인할 수 있습니다.
4. 변경 목록의 항목을 누르면 해당 위치로 화면이 이동합니다. 이동한 오브젝트는
   **원본 보기**에서 이전 위치, **수정본 보기 / 변경 강조**에서 현재 위치로 이동합니다.
5. **비교 닫고 편집** 또는 **Esc**로 편집 화면으로 돌아갑니다.

**변경 강조**는 수정본 위에 다음 표시를 겹칩니다.

| 표시 | 의미 |
| --- | --- |
| 파란 바닥 칸 | 직접 추가·변경·삭제한 바닥 셀 |
| 연한 주황 칸과 블록 점선 | 직접 바꾸지 않았지만 기존 4×4·2×2 블록 재구성에 포함된 주변 셀과 원래 블록 범위 |
| 주황 오브젝트 잔상·외곽선·화살표 | 이동 전 위치와 현재 위치, 이동 방향 |
| 초록 오브젝트 외곽선 | 새로 추가하거나 복제한 오브젝트 |
| 빨간 오브젝트 잔상·외곽선 | 삭제한 원본 오브젝트의 이전 위치 |
| 초록 / 빨강 빗금 셀 | 이동불가 셀 추가 / 해제 |

예를 들어 4×4 블록 안의 한 칸만 바꾸어도 나머지 15칸의 그림이 작은 타일 조합으로
재구성될 수 있습니다. **바닥 수정**과 **주변 타일 재구성** 수량을 분리해 표시하므로
직접 바꾼 범위와 출력 시 영향을 받는 범위를 함께 확인할 수 있습니다.

비교에는 수정본에서 사라진 원본 건물·나무·큰 바닥 타일의 이미지도 추가로 읽어
캐시에 보관합니다. 원본 그림의 크기·피벗·회전·배율을 사용하며, 이미지나 피벗을
확인하지 못하면 경고로 표시합니다.

비교 조작 자체는 프로젝트 저장, 후보 파일 생성, 게임 폴더 쓰기를 하지 않습니다.
수정 결과를 보관하거나 후보를 만들 때는 편집 화면의 **작업 저장 / 게임용 출력 만들기**를
사용합니다. 이 비교는 정적 배치 확인용이며 **Maker Refresh/Play 및 인게임 런타임 검증은
아직 수행하지 않았습니다.** NPC 배치표에 연결한 대기 외형 외의 실행 중 객체·애니메이션·효과는 비교 대상에 포함되지 않습니다.

## 후보 출력물 검토 (6차)

**게임용 출력 만들기**가 끝나면 출력 경로 옆의 **후보 출력 검토**를 누릅니다.
별도 창에서 적용 대상 파일, 변경 수량, 파일 검사 결과를 확인할 수 있습니다.

- 적용 대상은 후보에 기록된 맵 파일과, 수정한 경우의 `DT_Walk.csv` / `DT_NpcSpawn.csv`입니다.
  `reference/` 아래 CSV는 참고 사본이며 적용 대상에 포함되지 않습니다.
- **다시 검사**는 후보 생성 이후 게임 원본이나 후보 파일이 변경·누락되었는지 확인합니다.
  이동불가 후보는 CSV 전체 파일이므로, 다른 맵의 행만 바뀌어도 원본 불일치로 표시합니다.
- **파일 검토 통과**는 검사 시점에 파일이 일치한다는 뜻입니다. 게임 반영이나 Maker 실행
  검증이 끝났다는 뜻은 아닙니다. 실제 반영 직전에 다시 검사해야 합니다.
- **검토 요약 저장**은 파일을 다시 검사한 뒤 확인 시각·변경 요약·적용 대상·해시·문제 내용을
  텍스트로 저장합니다. 확인이 필요한 후보도 진단 기록을 저장할 수 있습니다.
- 맵을 더 수정하면 현재 작업의 후보 검토 버튼은 사라집니다. 이전 출력물은 **후보 기록**에서
  다시 확인하고, 현재 수정 내용의 출력물은 다시 구워 주세요. 검토 정보를 갖추지 않은 예전
  후보는 다시 구워야 합니다.

검토 창과 요약 저장은 게임 원본에 파일을 복사하거나 Maker를 실행하지 않습니다.
후보 폴더 전체 또는 `reference/`를 게임 폴더에 덮어쓰지 마세요.
실제 반영·백업·복구·Maker 검증은 별도 작업입니다.

## 후보 기록과 적용 파일 내려받기 (7차)

게임 맵을 연 뒤 **후보 기록**을 누르면 이 맵에서 구웠던 후보를 최신순으로 찾을 수 있습니다.
새로고침하거나 맵을 더 수정해도 이전 후보 기록은 남습니다. 생성 시각과 변경 수량, 현재
작업과 같은 기준인지 이전 기준인지를 구분합니다. 기록은 **구웠던 시점의 출력물**이며,
현재 편집 중인 내용과 같다는 뜻은 아닙니다. 기록을 열어도 편집 중인 맵은 바뀌지 않습니다.

1. 기록에서 후보를 골라 **후보 출력 검토**를 엽니다. 파일 검사는 열 때 새로 수행합니다.
2. **적용 파일 ZIP 받기**는 내려받기 직전에 다시 검사합니다. 게임 원본이나 후보가 바뀌거나
   누락되면 내려받기를 중단하고 문제를 표시합니다.
3. ZIP에는 검사를 통과한 적용 대상 맵과, 수정한 경우의 `DT_Walk.csv` / `DT_NpcSpawn.csv`, 그리고
   검사 시각·파일 해시·변경 내역을 담은 `REVIEW.txt`만 들어갑니다. 게임 폴더와 같은 상대
   경로를 유지하며, 참고 CSV나 에디터 프로젝트·기준 스냅샷은 넣지 않습니다.

목록 표시는 적용 가능 판정이 아닙니다. 실제 파일 검사는 후보를 열거나 내려받을 때 수행하며,
다운로드 이후 게임 원본이 바뀌면 다시 검사해야 합니다. ZIP 내려받기는 게임 반영을 실행하지
않습니다. 실제 반영·백업·복구·Maker Refresh/Play는 별도 작업입니다.

후보 목록은 최근 100개까지 표시합니다. 손상되거나 인식할 수 없는 기록은 건너뛰고 건수를
알립니다. 기준을 다시 가져온 뒤에도 이 맵의 이전 기준 후보를 찾을 수 있지만, 기준 폴더가
없거나 파일이 달라졌다면 검사를 통과할 수 없습니다.

## NPC 표시와 편집 (8차)

게임 맵을 열면 현재 기준의 NPC를 실제 대기 외형으로 표시합니다. 기존 작업을 다시
가져올 필요가 없습니다. 페른델은 9명이며 게임 전체 배치는 13명입니다. NPC는 게임이
배치표를 읽어 생성하므로, 맵 파일에 NPC 엔티티를 추가하지 않고 배치표 후보를 만듭니다.

1. 왼쪽 **NPC**에서 이름을 고르거나 **NPC 목록·편집(N)** 도구로 그림을 누릅니다. 목록에서
   고르면 해당 NPC 위치로 화면도 이동합니다.
2. 그림을 드래그하거나 방향키로 한 칸씩 옮깁니다. 선택한 NPC의 좌표·좌우 반전·대사 ID를
   바꿀 수 있고 **삭제**로 배치를 제거합니다. 종류를 고른 뒤 맵을 클릭해 새 NPC를 추가합니다.
3. 자동 저장 / **Ctrl+S**, **Ctrl+Z**로 되돌리기, **Ctrl+Y**로 다시 실행이 가능합니다.
4. **원본과 비교**에서 NPC 이동·추가·삭제·속성 변경을 따로 확인합니다. **게임용 출력 만들기**는
   NPC 변경이 있을 때만 NPC 배치 CSV를 추가합니다. 후보 검토와 ZIP에도 변경 수량이 표시됩니다.

게임 쪽 NPC 원본이 바뀌었으면 **NPC 원본 다시 불러오기**를 사용합니다. NPC 수정은 확인 후
초기화하지만 바닥·오브젝트·이동불가 작업은 유지하며, 이 동작도 한 번에 되돌릴 수 있습니다.
새 기준은 에디터의 `.game-sync/baselines/npc-<id>/`에 보관합니다. 별도 파일을 직접 선택하지 않습니다.

- 위치·반전·대사는 `DT_NpcSpawn`, 이름은 `ST_NpcName`, 크기와 대기 모습은
  `DT_NpcClass`·`DT_NpcAppearance`의 현재 게임 규칙을 따릅니다. 배치표의 Scale은
  현재 게임에서도 사용하지 않아 클래스 BodyScale을 사용합니다.
- 대기 리소스의 첫 프레임과 픽셀 오프셋, 원본 스프라이트의 최신 크기·피벗·PPU를 읽습니다.
  현재 13종은 한 프레임·한 레이어입니다. 지원하지 않는 합성은 경고로 표시합니다.
- NPC끼리 같은 칸에 새로 놓거나 맵 밖으로 옮기는 작업을 막습니다. 이동불가 칸 배치는
  카운터 안 NPC처럼 게임에도 있으므로 경고만 표시하며, 이동불가 데이터는 수정하지 않습니다.
- 현재 맵의 NPC 배치 또는 종류·외형·이름 원본이 바뀌면 NPC 후보 출력을 중단합니다.
  다른 맵의 최신 행과 수정하지 않은 행·추가 열은 원문 그대로 후보 CSV에 보존합니다.
- 이름·대기 외형·좌표를 표시하지만 대화 실행, 퀘스트 상태, NPC 애니메이션 재생과
  런타임 건물 가림 보정은 아직 Maker에서 대조하지 않았습니다. 게임 원본 적용과 Maker
  Refresh/Play는 이 작업에서 실행하지 않습니다.

### 몬스터·포털·시작 위치 편집

상단 **몬스터 / 포털 / 시작점** 도구에서 해당 목록을 엽니다. 현재 게임의
몬스터 15개 출현 지점(설정 수량 합계 250), 포털 50개, 13개 맵의 시작 위치를
게임 배치표에서 읽습니다. 예전 프로젝트의 개별 몬스터 마커를 다시 구워 넣지 않습니다.

- **몬스터**: 출현 지점 선택·이동·추가·삭제, 종류·동시 수량·분산 범위·재생성 시간·
  첫 등장 지연·활성을 편집합니다. 그림 한 개는 출현 기준점이며 실제 개체들의 고정 위치가
  아닙니다. 게임은 범위 안의 이동 가능한 빈칸에 나누어 배치합니다.
- **포털**: 출발 칸과 도착 맵·칸·방향·활성을 편집하고 추가·삭제합니다.
  한 방향 연결이며 반대편 포털은 별도입니다. 중복 출발 칸과 잘못된 도착지는 거절합니다.
- **시작점**: 해당 맵의 기본 시작 위치만 이동·재지정합니다. 맵 크기, 부활·귀환 정책,
  처음 접속할 맵은 바꾸지 않습니다. 삭제 기능은 없습니다.
- 선택 후 그림/마커를 드래그하거나 방향키로 이동합니다. 저장·다시 열기·Ctrl+Z/Y·
  원본 비교·후보 검토는 다른 배치 편집과 같은 흐름입니다.

수정한 종류에 한해 `monster/DT_MonsterSpawn.csv`, `DT_Portal.csv`,
`world/DT_Bounds.csv` 후보를 생성합니다. NPC와 이 세 배치만 수정하면 네이티브
`.map`은 바이트 그대로 보존합니다. 다른 맵 행과 미편집 열도 그대로 유지합니다.
**원본 다시 읽기**는 세 배치의 원본과 수정만 갱신하고 바닥·오브젝트·NPC·이동불가 작업을
유지합니다. 이 동작도 실행취소할 수 있습니다.

게임의 현재 맵 배치, 종류·외형, 포털 목적지·보행 조건 등이 바뀌면 오래된 기준으로
출력하지 않습니다. 현재 맵의 보행판 자체가 달라진 경우에는 전체 게임 맵 기준을
다시 가져와야 합니다. 후보 생성·검토·ZIP은 이 원본 조건을 각각 재검사합니다.

NPC의 새 대사 ID는 실제 `DT_QuestSequence.SequenceGroupID` 목록에서 확인합니다.
빈값은 게임의 기존 자동 대사 정책을 유지합니다. 기존 원본에 있는 값은 무변경 보존합니다.

NPC·몬스터·포털의 건물 앞뒤 깊이는 게임의 `scripts/depth_check.cjs`가 내보내는
검증된 계산을 현재 후보 맵에 적용합니다. 편집 좌표와 원본 파일은 바꾸지 않습니다.
대기 첫 프레임만 표시하며, 이동·전투·애니메이션 재생·플레이어 위치에 따른 가림물
투명화·대화 실행은 웹 미리보기 범위 밖입니다. 실제 Maker 화면과 실행은 별도 확인 대상입니다.
